# Web resources

Every external host this configuration talks to, grouped by why it is there, plus
where the Nix parts of it live. "External" means reachable off the machine: flake
inputs, binary caches, API endpoints, ACME, and the served hostnames. Ports that
only bind to loopback are listed separately at the end.

Every repository and endpoint below is a link you can click. Local paths are
backticked, not linked, because they are on your filesystem.

Three rules this document follows:

- **Nothing here is a secret.** Hostnames, repository URLs, and ports are public.
  Tokens, keys, and record values are not listed and never should be — see
  [`docs/security.md`](security.md).
- **Direct versus transitive is stated.** A repo pulled in by another flake is not
  something you chose directly, and pinning it yourself would be wrong.
- **The `github:` shorthand resolves to HTTPS.** `github:owner/repo` means
  `https://github.com/owner/repo`, so each row links the real destination.

## 1. Where the Nix lives

Start here if you are looking for "the config". The repository is
[github.com/elkebirmed/nixconfig](https://github.com/elkebirmed/nixconfig); this
section is the map of it.

### Top level

| Path         | What it is                                              |
| ------------ | ------------------------------------------------------- |
| `flake.nix`  | Generated. Inputs live here; edit the aspect, not this. |
| `flake.lock` | Pinned revisions of all 43 nodes.                       |
| `modules/`   | Everything else. 99 `.nix` files.                       |
| `secrets/`   | SOPS-encrypted; safe to commit, keys never are.         |
| `infra/dns/` | OpenTofu DNS, deliberately outside the flake.           |
| `scripts/`   | `privacy-scan.py` and helper scripts.                   |

`flake.nix` is generated by [`flake-file`](https://github.com/vic/flake-file)
from `flake-file.inputs.*` declarations scattered across aspects. That is why an
input is declared next to the feature that needs it, and why `nix run .#write-flake`
regenerates the root file. Editing `flake.nix` directly gets overwritten — CI
fails on exactly that, in the "Ensure flake.nix is regenerated" step.

### The two hosts

| Host    | Declared in               | SSH reachable on   | Storage                 |
| ------- | ------------------------- | ------------------ | ----------------------- |
| `vps`   | `modules/hosts/vps.nix`   | `tailscale0` only  | ext4, BIOS boot         |
| `crazy` | `modules/hosts/crazy.nix` | `enp9s0`, `wlp8s0` | Btrfs, impermanent root |

`vps` includes `web`, `quadlet`, `private-app`, `monitoring`, `backups`,
`tailscale`, `openclaw`, `server-nix`, `server-misc`. `crazy` includes the
desktop stack: `niri`, `noctalia`, `zen-browser`, `nvf`, `impermanence`.

They share only generic aspects — users, SOPS plumbing, firewall, locale.
Putting a server aspect on `crazy` is a bug, not a convenience.

## 2. Deploying

See [`docs/deploy.md`](deploy.md) for the full workflow. The short version:

```bash
nix run .#vps                      # build through nh, no switch
sudo nixos-rebuild switch \
  --flake github:elkebirmed/nixconfig#vps \
  --target-host ops@VPS_SSH_ALIAS \
  --build-host ops@VPS_SSH_ALIAS \
  --elevate=sudo
```

`--build-host` matters on a small box: it builds with the target's memory rather
than whatever the caller has. Nothing deploys automatically — no auto-upgrade
timer, no CI deploy job. A merge is not a deploy.

## 5. Binary caches

| Cache                                              | Scope   | Trust                             |
| -------------------------------------------------- | ------- | --------------------------------- |
| [cache.nixos.org](https://cache.nixos.org)         | both    | NixOS default key                 |
| [noctalia.cachix.org](https://noctalia.cachix.org) | desktop | `noctalia.cachix.org-1:pCOR47nn…` |

`noctalia.cachix.org` is declared twice — in `flake.nix` (`nixConfig`) and in
`modules/aspects/desktop/cache.nix` — so `--accept-flake-config` works before the
rebuilt system's settings are live.

**Deliberately absent:** `niri-epireyn.cachix.org`. niri comes from `pkgs.niri`
instead, so no third-party substituter is trusted just to get a session module.
The cost is that niri releases lag until nixpkgs bumps them.

## 6. AI and model providers

| Endpoint                                        | Used by                      |
| ----------------------------------------------- | ---------------------------- |
| `https://api.commandcode.ai/provider`           | Minuet, CodeCompanion (nvf)  |
| `https://api.commandcode.ai/provider/v1`        | OpenClaw, OpenCode           |
| `https://api.commandcode.ai/provider/v1/models` | Catalog; source of model IDs |

These are API base URLs, not pages. GET returns 404 for the first two, which is
correct rather than broken, so they are backticked instead of linked. The catalog
is the exception: it answers an authenticated GET, and it is the authority for
which model IDs exist.

Defined once in `modules/aspects/ai/_commandcode-lib.nix` and imported by all
three consumers. Two URL forms exist because clients differ: the nvf adapters
append `/v1/chat/completions` themselves and need the bare root, while OpenClaw
and OpenCode expect the base with `/v1` already included.

The opencode JSON schema is fetched by the tool, not by Nix:
[opencode.ai/config.json](https://opencode.ai/config.json).

## 8. Served hostnames (Caddy)

Inbound, not outbound. Four sites on the VPS; the domain is a SOPS placeholder
(`{$WEB_DOMAIN}`), never a literal.

| Site             | Backend           | Access    |
| ---------------- | ----------------- | --------- |
| apex             | static example    | `public`  |
| `openclaw.<dom>` | `127.0.0.1:18789` | `tailnet` |
| `grafana.<dom>`  | `127.0.0.1:3000`  | `tailnet` |
| `metrics.<dom>`  | `127.0.0.1:9090`  | `tailnet` |

Unknown subdomains are aborted — the wildcard block ends in `handle { abort }`.

## 9. TLS and DNS automation

| Service                                                         | Role                               |
| --------------------------------------------------------------- | ---------------------------------- |
| [Let's Encrypt](https://letsencrypt.org)                        | Caddy's default ACME CA, DNS-01    |
| [Cloudflare](https://www.cloudflare.com)                        | Zone DNS and ACME challenge target |
| [caddy-dns/cloudflare](https://github.com/caddy-dns/cloudflare) | Caddy plugin, v0.2.4               |
| [registry.opentofu.org](https://registry.opentofu.org)          | `cloudflare/cloudflare` 4.52.10    |

The ACME endpoint is not written out in source — it is the provider default,
reached through the socket the Caddy plugin opens. Two separate tokens are used:
one for Caddy's challenge, one for `infra/dns/`, so rotating either does not
touch the other.

## 10. CI

The workflow is `.github/workflows/test.yml`, with every action pinned to a
commit SHA:

| Action                                                                                                    | Purpose             |
| --------------------------------------------------------------------------------------------------------- | ------------------- |
| [actions/checkout](https://github.com/actions/checkout)                                                   | Checkout, v7.0.1    |
| [DeterminateSystems/nix-installer-action](https://github.com/DeterminateSystems/nix-installer-action)     | Nix on runner, v23  |
| [DeterminateSystems/magic-nix-cache-action](https://github.com/DeterminateSystems/magic-nix-cache-action) | Build cache, v15    |
| [DeterminateSystems/update-flake-lock](https://github.com/DeterminateSystems/update-flake-lock)           | Weekly lock PR, v29 |

Runs on `ubuntu-latest`: every push, every PR, and Monday 04:00 UTC. It builds
both `vps` and `crazy` toplevels, so a push that breaks either host fails before
merge.

## 11. Container images

No image is hardcoded. `private-app.nix` requires each app's image reference to
come from a SOPS secret (`secretName`), so no registry path or digest is ever a
Nix literal. No apps are defined today, so there are no live registry pulls.

## 13. Not configured

Absence is a decision here, and worth seeing as clearly as the contents:

- **No web search provider.** OpenClaw has no `tools.web`; the assistant fetches
  only URLs it is given.
- **No telemetry.** Enforced, not merely absent: Grafana sets
  `analytics.reporting_enabled = false` and `check_for_updates = false` in
  `modules/aspects/server/monitoring.nix`.
- **No auto-upgrade.** No `system.autoUpgrade` anywhere; `vps` garbage-collects
  weekly, and `crazy` uses `nh clean`. Neither rebuilds on its own.
- **No third-party DNS resolvers.** No `nameservers` or `dns` override exists, so
  systemd-resolved defaults apply.
- **No external object storage named here.** Backups use `restic`, whose
  repository is a SOPS secret — the destination is deliberately not in git.
- **No Kubernetes, k3s, Argo CD, Helm, or Komodo.** Quadlet only, by rule.
